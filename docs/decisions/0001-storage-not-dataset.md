# ADR-0001：用户文件走对象存储，数据集只做镜像/冷备

- 状态：已接受
- 日期：2026-11-27

## 背景

初版规划把「用户上传文件」放在 ModelScope 私有数据集里。阶段 0 审计（modelscope 1.40.3 /
modelscope_hub 0.7.2，官方文档 + 源码 + 运行时实测）发现三条结构性冲突：

1. **写模型是 commit + LFS**：图片后缀强制 LFS、>64KB 强制 LFS；一张头像 = blob 校验 + PUT +
   一条 commit。官方明确反对「一文件一 commit」，且 commit 频率**动态限流、不公开、不可提额**
   （modelscope#1793）。
2. **私有 = 整仓**：没有对象级 ACL，没有文档化的签名 URL 发行 API；给第三方读取只能给账号级
   token（泄漏=全账号）或未文档化的 ~12h STS 凭据。
3. **删除不可编程**：删文件也是 commit（历史仍可读），整仓删除只能网页控制台、不可撤销。

## 决策

- 用户文件（头像、聊天图片、附件）**一律走对象存储**（`storage.Provider`），客户端只拿短时
  签名 URL；
- 数据集（`dataset.Provider`）**只做公开素材镜像与冷备**，接口刻意不提供「单用户隔离」语义；
- `dataset` 包的文档注释里写明禁止用途，防止后续误用。

## 后果

- 需要对象存储的账号/桶/备案域名（APK 分发在部分厂商必须自定义域名）；
- 分片续传要自建 checkpoint（多数云 SDK 不提供）；
- 公开素材仍可用数据集做源，配 CDN 分发，成本低。

## 替代方案

- 全部走数据集：被上述三条否决。
- 自建 MinIO：可行，作为 `storage.Provider` 的另一实现，适合内网/自托管场景。
